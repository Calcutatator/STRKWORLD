# STRKWORLD API and credential readiness

**Checked:** 2026-08-19. This is an inventory, not a request for secrets. Do
not paste keys into chat, Git, Docker build arguments, or browser source.

## Needed now — local development and offline UI work

- **No paid API account is required for the current offline game.** The
  checked-in web composition uses deterministic demo privacy/Bridge services;
  the local lobby runs with `npm run dev --workspace=@strkworld/lobby` on
  `ws://localhost:2567`. If `VITE_LOBBY_URL` is absent or malformed, the web
  app deliberately stays in solo mode (`README.md`, `apps/web/src/presence/config.ts`).
- **A browser wallet is useful for UI composition testing, but not required for
  unit tests or the offline demo.** It becomes required for the funded Wallet
  API run described by D-028.
- **No NEAR Intents/1Click JWT is needed for v1's direct unauthenticated route.**
  The official 1Click documentation says unauthenticated requests are
  supported but charge a 0.2% platform fee; JWT authentication is the route to
  fee-free platform access. [1Click authentication](https://docs.near-intents.org/integration/distribution-channels/1click-api/authentication)
  and [official fee table](https://docs.near-intents.org/resources/fees).

## Needed before funded validation or production

- **Funded wallet and compatible Wallet API implementation.** D-028 requires a
  mainnet run covering the visible prompt sequence, latency, wallet-produced
  artifact compatibility, and AVNU paymaster acceptance. The wallet must be
  funded and the run must use a deliberately small amount; no key is supplied
  by this project.
- **Server Starknet RPC provider/key:** `STARKNET_RPC_URL`. It is a secret in
  the backend because the URL embeds the provider key. The provider, quota,
  mainnet endpoint, and server-side restriction are still deployment choices.
- **Browser Starknet RPC key, if the final build keeps direct public reads:**
  `VITE_STARKNET_RPC_URL`. Vite publishes it to every player, so it must be a
  domain-allowlisted/read-only key and must be distinct from the server key.
  Recipient-linked or timing-sensitive reads remain backend-proxied under
  D-014; this is documented in `.env.production.example` and `docs/OPS.md`.
- **AVNU paymaster account, API key, and funded sponsorship credits:**
  `AVNU_PAYMASTER_API_KEY` is server-only and spends sponsorship budget. AVNU's
  official gasfree guide requires a Portal account, an API key, and mainnet
  credits; its gasless mode does not require a key but is not the selected
  sponsored route. [AVNU gasfree setup](https://docs.avnu.fi/docs/paymaster/gasfree).
- **Generated fee-authorization secret:** `FEE_AUTHORIZATION_SECRET`, at least
  32 characters, injected at runtime and rotated using the documented overlap
  procedure. It is generated by us, not purchased from a provider.
- **Production hosting, domain, same-origin routing, and secret custody.** A
  chosen host must serve the static web app and backend under one origin (the
  backend intentionally emits no CORS headers), provide runtime secret
  injection, and support a production `wss://` lobby endpoint plus an explicit
  browser-origin allowlist. These remain open in `docs/OPS.md`; no vendor or
  domain should be assumed.
- **Production lobby deployment.** The local Colyseus server is implemented,
  but production packaging/host/TLS is not. `VITE_LOBBY_URL` must be a chosen
  `wss://` endpoint and its allowlist must match the deployed web origin.

## Not needed for the approved v1 route

- **1Click JWT/API key for ordinary direct quotes:** not needed; it only avoids
  the documented unauthenticated 0.2% platform fee. A JWT must not be bundled
  into Vite or stored in the browser. If authenticated distribution is later
  chosen, that is a separate provider/account decision.
- **A prover, discovery service, viewing key, note store, or user private key:**
  explicitly not needed and prohibited by D-002. The wallet owns privacy
  infrastructure.
- **An AVNU paymaster key in the browser:** prohibited. The selected paymaster
  custody is backend-only.
- **A fixed pool-fee constant or production public-shield planner:** not
  available yet. D-043 keeps the real Bridge-to-Bank handoff locked until the
  fee-aware route is source- and funded-verified; the deterministic planner is
  offline-only.

## Repository authority and verification boundary

The variable names and custody classifications above come from
`.env.production.example`, `apps/backend/src/environment.ts`, `docs/OPS.md`,
and D-028/D-043 in `docs/DECISIONS.md`. Provider claims were checked against
